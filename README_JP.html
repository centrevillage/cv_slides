cv_slides 利用マニュアル

Markdown と画像から、オフラインで動く単一 HTML のスライドを生成するツール。

feat/slide-generator ブランチ(M0〜M5 実装済み)の実装に基づく。2026-10-14 時点。

1概要

  • slides/<name>/<name>.md と画像から HTML ファイルを1つ生成する。CSS・JS・画像・ハイライト済みのコード・数式はすべて HTML に埋め込まれ、外部とは通信しない。file:// で開いてオフラインで発表できる。
  • 重い処理(Markdown の解析、Shiki によるハイライト、KaTeX による数式の MathML 化、画像の Base64 化)は生成時に済ませる。出力 HTML に第三者のライブラリは入らない。
  • 同じ入力からは同じ HTML ができる(生成日時などを埋め込まない)。Git で差分を管理しやすい。
  • スライドは 1920×1080(16:9)の固定キャンバスに描き、画面に合わせて拡大・縮小する。サムネイル・通常表示・全画面で改行位置は変わらない。
  • ページ種別: タイトル / コンテンツ / 高橋メソッド / コードサンプル(JavaScript を実行。コンソール・音声・WASM)/ 全面画像。
  • 見た目はデザインテンプレート(designs/<name>/)で切り替える。同梱は default(白)と dark(黒)。
  • ブラウザの印刷機能で、1スライド1ページの PDF を作れる。
ビューアのモード画面主な用途
ナビゲーション(起動時)左にサムネイル一覧、右に選択中のスライド。縦長の画面では上にスライド、下に一覧作成中の確認、スライドの選択
プレゼンテーション選択中のスライドを全画面に表示(余白は黒)発表

4コマンド

./gen_slide.sh <slide> [オプション]   スライドを生成
./gen_slide.sh --all [オプション]     slides/ 以下のスライドをすべて生成
./gen_slide.sh <slide> --watch        ファイル変更を監視して自動再生成(Ctrl+C で終了)
./gen_slide.sh new <name>             slides/<name>/ に雛形を作成

gen_slide.sh は node scripts/cli.ts を呼ぶだけ。どのディレクトリからでも実行できる。スライド名と designs/ はリポジトリ基準、md のパスと -o はカレントディレクトリ基準で解決する。

<slide> の指定

書き方読むファイル
foo(/ を含まず .md で終わらない)slides/foo/foo.md
slides/foo/foo.md、../talk.md など(/ を含むか .md で終わる)そのファイル
ディレクトリのパス(例: slides/foo)slides/foo/foo.md(<dir>/<dir の名前>.md)

オプション

オプション内容
-o, --out <path>出力先。既定は md と同じ場所・同じ名前の .html。親ディレクトリがなければ作る。入力と同じパスはエラー

エラーになる組み合わせ: --all と <slide> / --out / --watch、new とオプション、<slide> を2つ以上。

メッセージと終了コード

  • 警告・エラーは標準エラーに ファイル:行: 警告: [スライド N] 内容 の形で出る。N は出力 HTML のページ番号(自動のタイトルページを含む。サムネイルの番号・URL の #N と同じ)。
  • 成功すると標準出力に 生成しました: 出力先(スライド N 枚、警告 M 件)。
  • エラーがあると 生成を中止しました: …(エラー X 件、警告 Y 件)。HTML は書き出さない(既存の HTML はそのまま残る)。
  • --all は最後に 全 N 件: 成功 X 件、失敗 Y 件。
結果HTML終了コード
成功(警告のみを含む)書き出す。問題の箇所は無視するかプレースホルダにする0
警告あり + --strict書き出さない1
エラーあり書き出さない1
引数の誤り、md がない、UTF-8 でない—1
--all で1件でも失敗成功した分は書き出す1
--watch を Ctrl+C で終了—0

--watch

  • 最初に1回生成し、以後は変更のたびに再生成する(200ms のデバウンス)。「変更を検知しました」と結果の行の先頭に [HH:MM:SS] が付く。
  • 監視するもの:
    • md ファイル
    • md と同じフォルダの img/ 以下すべて(サブフォルダ・新しいファイルを含む)
    • 生成時に読んだファイル: 参照している画像・アイコン・アセット。見つからなかったものも含む(作ると再生成される)
    • 使っているデザインのフォルダ designs/<name>/ 以下
    • scripts/runtime/ の viewer.js・viewer.css・runner.js
  • 監視しないもの: 出力 HTML、上記以外のファイル、生成ツール本体(scripts/build/、scripts/languages/ など。変えたら --watch を起動し直す)。
  • 生成に失敗しても監視は続く(HTML は前回のまま)。
  • ブラウザは自動で再読み込みしない。再読み込みしても URL の #N で同じスライドが開く。
  • 監視できるのはスライド1つだけ。-o・-d・--strict は併用できる。

new <name>

  • slides/<name>/<name>.md(雛形 scripts/templates/new_slide.md のコピー)と slides/<name>/img/.gitkeep を作る。
  • 名前に使えるのは英数字・-・_。同名のフォルダがあればエラー(上書きしない)。
  • 雛形: フロントマター(title・subtitle・author・date・event、コメントアウトした icon・design)と、コンテンツ・高橋メソッド・コードの3枚。そのまま警告なしで生成できる。

例

./gen_slide.sh test_slide                    # slides/test_slide/test_slide.html を生成
./gen_slide.sh test_slide -d dark -o /tmp/test_dark.html
./gen_slide.sh slides/test_slide/test_slide.md --strict
./gen_slide.sh --all
./gen_slide.sh my_talk --watch

フロントマター

1行目が --- のときだけ、次の --- 行までを YAML 1.2(Core スキーマ)として読む。閉じていなければエラー。

キー型既定内容
title文字列—タイトル。空でなければタイトルページを自動で作る。<title> にも使う(未指定なら md のファイル名)
subtitle文字列—サブタイトル
author文字列—発表者名(タイトルページの右下)
date文字列—書いたまま表示する(日付として解釈しない)。2026-11-03 は引用符なしでも文字列になる。2026 のような数字だけの値は "2026" と囲む
event文字列—イベント名。「イベント / 日付」の形で表示
icon文字列—発表者アイコンの画像パス(md からの相対)。発表者名の左に円形で表示
design文字列defaultデザイン名(-d が優先)
page_numbertrue / falsetrueページ番号を表示するか
  • すべて任意。未知のキーは警告。型が違う値(数値・真偽値・リストなど)はエラー。yes / on は文字列になるので、page_number には true / false を書く。

注意: 値の途中の「空白 + #」以降は YAML のコメントになり、警告なしで消える。event: Audio Dev Meetup #12 は「Audio Dev Meetup」と表示される。# や : を含む値は "…" で囲む。

スライドの区切り

  • ハイフン3つ以上だけの行(---。行頭の空白3つまで・行末の空白は可)で区切る。
  • フェンスコードブロック(``` / ~~~)の中の --- は区切りにならない。
  • このため --- の水平線と、--- を下線に使う見出しは使えない。水平線は *** か ___ を使う。
  • 中身が空のスライド(区切りの連続など)は警告して無視する。

ディレクティブ

スライドの最初の行(空行を除く)に、1行の HTML コメントで書く。key: value をカンマで区切る。

<!-- page: image, fit: contain, class: inverse -->
キー値内容
pagetitle / content / takahashi / code / imageページ種別。未知の値はエラー
classデザインの classes にある名前(スペース区切りで複数可。英数字・-・_)<section> に slide--class-<名前> が付く。デザインにない名前は警告(クラスは付く)

  • 最初のキーが page / class / fit でないコメント(<!-- memo: … --> など)は普通のコメント。2行目以降に書いたディレクティブも普通のコメントになる。
  • 未知のキー・重複したキーは警告(重複は後の値を使う)。

タイトルページ

  • 自動: フロントマターの title が空でなく、1枚目が page: title でなければ、先頭に挿入する。タイトル・サブタイトル・アイコン・発表者・イベント / 日付を表示する。
  • 明示: # の見出しがタイトル、続く段落1つがサブタイトル。ほかの要素は警告して無視する。見出しの中のインライン記法は使える。
    • 1枚目に置くと自動のタイトルページの代わりになり、フロントマターのアイコン・発表者・イベント・日付も表示する。見出しがなければフロントマターの title / subtitle を使う。
    • 2枚目以降(セクションの扉)では見出しと段落だけを表示する。
  • タイトルページにはページ番号を出さない。class を付けたいときは明示のタイトルページを書く(自動のページにはディレクティブを書けない)。

# 第2部: 実装編
ハードウェアとの付き合い方

コンテンツページ

  • 先頭のブロックが ##(または #)ならページタイトルになる。なければ本文だけを表示する。
  • ### は小見出し。本文の途中の # は ## と同じ見出しとして出力する。
  • 本文は上揃え。画像は本文の残りの高さに収まるよう縮小する。文字は縮小しない。本文がはみ出すと、はみ出した部分は切り取られ、一覧に ⚠ が付く(→ 13)。

高橋メソッドページ

<!-- page: takahashi -->

**書く**

# 書く
  • 1つの改行が1行になる。自動では折り返さない。

項目仕様
形式jpg / jpeg / png / gif / svg / webp / bmp(拡張子で判定、大文字小文字は区別しない)。ほかは警告してプレースホルダ
パスmd ファイルからの相対パス。?… と #… は無視。日本語のファイル名も可。空白を含むパスは %20 にするか <…> で囲む。data:image/png・gif・jpeg・webp の data URI はそのまま使える
配置画像だけの段落がブロック画像になる。1段落に複数の画像があれば、それぞれ別のブロック(縦に並ぶ)
キャプション画像のタイトル "…" を画像の下に中央揃えで表示
大きさ既定は本文の残りの高さに収まる大きさに縮小して中央に置く(拡大しない)。{width=60%}(本文の幅に対する割合)か {width=800px}(キャンバス座標)で幅を指定できる。ほかの単位は警告して無視。width 以外の属性({height=…}、{.class} など)は警告なしで捨てる
埋め込みBase64 の data URI。同じ画像を何度参照しても、ファイルの読み込みは1回だが、HTML には参照ごとに埋め込まれる
2MB 超警告して、縮小せずに埋め込む。事前に縮小する(例: sips -Z 1920 photo.jpg)。警告はファイルごとに1回

順処理
1NaN / ±Infinity を 0 に置き換える。検出するとコンソールに「[リミッター] NaN / Infinity を検出したため 0 に置き換えました」(1回の実行につき1回)

  • コードはサンドボックス化した iframe(sandbox="allow-scripts"、srcdoc)の中で動き、スライド本体の DOM や状態には触れない。iframe はボタンの行だけなので、画面に描く場所はない(出力はコンソールと音声)。
  • Web Audio(AudioWorklet を含む)と WebAssembly を使える。外部のライブラリは読み込めない(オフライン前提)。必要なファイルはアセットで埋め込む。
  • SharedArrayBuffer は使えない(file:// では COOP / COEP ヘッダーを設定できない)。メインスレッドと AudioWorklet の間は MessagePort でやりとりする。
  • 同期的な無限ループは、ページ全体を固めることがある。
  • 発表中のコードの編集はできない(表示のみ)。Onsa のコードは表示とハイライトだけ(WASM での実行は未対応)。
  • iframe にフォーカスがあっても、ページ送り・モード切り替えのキー(矢印、Space、PageUp / PageDown、Home / End、Enter、Tab、Esc)は親ページに転送される。コード・パネルの上のクリックとホイールはページ送りにならない(コードとコンソールがスクロールする)。
  • サムネイルでは実行環境を作らない。印刷ではコードだけを出す。
  • 動作は Chrome で確認済み(file:// でも AudioWorklet・Blob URL・WASM が動く)。ほかのブラウザは確認していない。

新しいデザインを作る

  1. cp -R designs/default designs/mydesign(フォルダ名は英数字・-・_)
  2. design.json の highlightTheme と classes を決める。
  3. design.css の CSS 変数を変える。足りなければセレクタを書く。
  4. ./gen_slide.sh my_talk -d mydesign --watch で確認する(designs/mydesign/ も監視される)。
  5. 決まったらフロントマターに design: mydesign を書く。

design.json が JSON として読めない・オブジェクトでない・型が違う、design.css がない場合はエラー。

design.css の規則

  • 出力 HTML の <style> にそのまま入る(ビューアの CSS のあと)。url() の中身は埋め込まれないので、外部の URL やファイルを参照しない(画像やフォントが必要なら data: URI で書く)。
  • セレクタは .slide から書く(#deck を前に付けない)。サムネイルはスライドの複製を一覧ペインに置いたもので、#deck の外にあるため。一覧ペインにも design-<名前> クラスが付くので、.design-mydesign .slide のような絞り込みは使える。
  • 寸法はすべて 1920×1080 のキャンバス座標の px で書く。.slide の大きさ・overflow・position は変えない(ビューアが固定している)。.viewer… のクラス(一覧・ボタンなど)はビューアの担当なので触らない。
  • デザインが用意するもの: ページ番号 .slide__page-number の配置(ビューアが要素を足すだけ)、実行できないコードサンプルページの文言(default では .runner[data-runnable="false"] .runner__frame-slot::before の content)、.slide__body の overflow: hidden(はみ出しの判定に使う)。
  • Shiki は色をインラインで指定する。背景を変えるときは pre.shiki.github-light などに !important で指定する。ハイライトしないコードは pre.shiki.plain。

18制限事項・サポート外

  • アニメーション(ページ切り替えのトランジションを含む)。
  • 行内の画像・行内の複数行コード片(行内画像は警告付きで出力するが、レイアウトは保証しない)。
  • 多言語対応(メッセージは日本語のみ、出力は <html lang="ja"> 固定)。
  • 動画・音声ファイルの埋め込み(サムネイルでは <video>・<audio>・<iframe> は空の枠になる)。
  • 発表者ビュー・発表者ノートの表示(<!-- note: … --> は予約のみ)、画面のブラックアウト。
  • 図(Mermaid など)、脚注、タスクリスト。
  • 縦横比は 16:9(1920×1080)のみ。
  • 画像の自動縮小(2MB 超は警告のみ)、URL 指定の画像。
  • 同じ画像を複数回参照すると、参照ごとに HTML に埋め込まれる(ファイルが大きくなる)。
  • CLI からの PDF 生成(ブラウザの印刷を使う)、GUI での編集。
  • コードサンプルページ: 実行できるのは JavaScript だけ。Onsa の WASM 実行、発表中のコード編集、外部ライブラリ、SharedArrayBuffer、画面への描画は使えない。同期的な無限ループは止められないことがある。
  • はみ出しの ⚠ はコンテンツページだけ。コードサンプルページ・タイトルページのはみ出しは検出しない。
  • ハイライトのテーマは github-light / github-dark だけ。言語の追加には生成ツールの変更が必要。
  • デザインのフォントや画像を埋め込む仕組み(fonts/・assets/)はない。design.css はそのまま入る。
  • --watch はブラウザを自動で再読み込みしない。監視できるのは1スライドだけ。
  • 生 HTML をサニタイズしない。他人が書いた Markdown を変換する用途には使わない。
  • 動作確認は Chrome のみ。Safari / Firefox / Edge は未確認。iPhone では全画面にならない。
